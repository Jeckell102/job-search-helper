# Samtec recipe v2 staging

This isolated stage extends the host-written v1 recipe with a Samtec-only HTML description fallback when the normal JSON-LD path has zero JobPosting objects. Generic structured extraction and other providers remain unchanged. The accepted earlier route patch is AI-authored; listing, transport, and detail implementations here are host-written Python. The Jetson chooses bounded evidence IDs, not arbitrary source code.

The strict configuration has exactly eight string fields: listing=full_search, container=job_list, pagination=next_link, range=displayed_range, detail=full_description, detail_title=listing_heading, detail_identity=company_and_apply_id, detail_location=detail_meta. Unknown/missing fields, unsupported IDs, duplicate JSON keys, arbitrary URLs or code are rejected. The build verifies the original route-only source SHA256 and both static helper hashes before returning content and patch; it never installs.

Detail fallback binds COMP-0739/Samtec, exact Jobvite host and slug, listing ID, unique matching heading, unique complete description, nested employer marker, exact matching apply href and metadata. Scripts/styles do not supply evidence. The complete description includes qualifications and EEO/footer text. Metadata splits department at the first actual separator; all remaining location segments are preserved with semicolons. Unfinished, duplicate, contradictory or missing evidence fails closed. Apply URLs are validated but never fetched.

Author checks: seven tests pass, including all 148 saved HTML descriptions compared in full with an independent extractor. The final selection and build receipt bind the actual Jetson recipe-selection-2 response by SHA256; rebuilding from those eight IDs produces the identical reviewed candidate. Fresh independent QA and live normal-dispatch validation are separate gates. Historical failure analysis files retained here are explicitly diagnosis of live-recipe-1, not v2 PASS certification.
