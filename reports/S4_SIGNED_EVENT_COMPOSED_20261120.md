The disposable candidate can stage one exact eligible event with the existing
scraper and writer admission. Staging requires the exact retained manifest,
event ID, Company ID and source revision. It writes the reserved request and
bridge acknowledgement and receipt. It does not create a Google client, call
the provider or enable the dispatcher.

The separate event signature binds the staged request, receipt, Company row,
historical scope, runtime and compact workbook controls. The existing
signed operator action retains its prior scope. Ordinary and legacy retained
entry points reject the manual marker. A synthetic fixture used the SQLite
outbox and normal filtering with a compact Sheets API fixture. It verified
exact sync, preserved prior job/review and historical controls, and replayed
the same terminal output without provider or remote access.

The combined regression passed 171 tests. These tests used disposable databases
and the local fake Sheets service.

The staged selected receipt transport is included separately in this
checkpoint. The exact retained outcome producer, typed failure handling,
end-to-end classified delivery and retry routing, independent QA, and live
acceptance remain open. Production was not changed.
