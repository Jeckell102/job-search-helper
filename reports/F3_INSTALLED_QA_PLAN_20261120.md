# Sprint 1 installed acceptance

The release owner must retain the deployment and recovery records. A reviewer independent of implementation must record an installed verdict before the Sprint 1 goal pause.

1. Record the exact installed 13-file hash and mode manifest and compare it with the accepted source. Compare the remainder of the package with the recorded pre-maintenance inventory. Inspect the controller's terminal record and the installer's bound receipt. Verify that the package currently visible is the original package directory with the accepted files and that the transient guards have been released.
2. On MuleLab, verify the actual public shell helpers and installed console in help mode. Read the installed runtime source, configuration and dependency digests without constructing a remote client. Keep the Samtec start and the retained cycle held. Verify the wrapper host is restored, its scheduler and supervision locks have one owner, and sync remains disabled and inactive with its original configuration.
3. Compare protected-state hashes against the private pre-maintenance capture, including the historical cycles database, inventories, jobs, Samtec request, receipt and latest lifecycle control. If any differ, investigate and identify the actual writer before accepting. Recheck queue, campaign, autopilot, company intake, retained intake, temporary retry, pending inference, and pending wrapper deliveries. Keep job data, raw request content and credentials off GitHub.
4. Exercise the subprocess release/start/rollback tests and version-binding evidence in a disposable credential-free tree using the exact installed source bytes. Verify which code was actually imported. Preserve the independent fixture evidence for interruption, rollback and the publication cutover. Use no production scrape or Sheets write as a smoke test.
5. Save the independent verdict, exact deployed identity, service restoration and protected-data comparison. If QA rejects, preserve the failure report, assign the smallest repair and reverify. Push only the scoped source, tests, plans and sanitized reports. Verify the private remote branch hash and record it in the restart card.
6. Pause the existing six-milestone goal once independent deployed QA and backup verification have passed. Sprint 2 starts only after the operator resumes on their chosen model.
