## Required transaction and witness

1. **Prepare and pin.** Pause known launch sources and check that production dependencies, credentials and stores can operate while all three names are closed. Use one private 0700 directory on the same durable mount, outside all checkouts, State and known launcher discovery paths. In one slot per checkout prepare a distinct, empty, real 0500 directory owned by the controller. Pin both parents, each original and sentinel by device/inode, roles, mode, owner and mount identity. Verify permissions/ACLs, absence of symlinks along the path, blocking inode flags, mountpoint or nested mount conflicts, and unexpected aliases. Pin the verified original launcher identities. Reject conflicting journals or slots. Durably record all three intended exchanges before the first one.
2. **Exchange and reconcile.** Under a controller lock, use directory-descriptor-relative Linux atomic exchange of the canonical name with its pinned slot. Sync both parent directories before recording each completion, and durably sync journal updates. A valid open pair has the original at the canonical name and the sentinel in its slot. A closed pair has the exact reverse. On interruption re-open both endpoints against the pinned parents, reconcile either valid pairing with the durable direction, re-sync and continue. An absent, substituted or unexpected endpoint blocks the entire production transition. Verify emptiness and denied launcher lookup from each supported execution context. No partial set of closed pairs authorizes installation, rollback source changes or a pilot.
3. **Drain after closure.** Account for already loaded interpreters, services, children, shells with a working directory under the parked tree, directory/file descriptors, old bind aliases, pending deliveries and in-flight writers. Such references can survive an exchange. Resolve recognized scheduling and module-entry contexts: PATH search, editable installs and Python fallback may select production or another installation. A missing alternate script proves only that lookup. An existing writable SQLite constructor can run before its writer lock. An unverified supported fallback, surviving launch-capable context or unresolved delivery leaves the hold incomplete. Preserve production's independent wrapper and scraper controls. 4. **Maintain and restore.** Verify all closed pairs and drain evidence at the joint checkpoints and before manual dispatch, including recovery after controller or manager restart. The closed names persist across process exit. Boot recovery must recheck persistent storage and actual namespace views before admitting work. Keep alternates closed through joint install or source rollback, the pilot, and terminal settlement of associated work. After that boundary, record restore intent, exchange each verified closed pair back, sync both parents and verify original root and launcher identities. Resume only the transaction's recorded launch controls. Interrupted restore resumes its recorded direction; protect any subsequent source change with a fresh all-closed proof.

## Acceptance boundary

Keep the current root-mount verifier intact. Add a distinct exchange witness that checks both pinned endpoint pairs, controller journal identity/generation and phase, ownership, mode, mount and canonical launch visibility. An arbitrary empty directory is insufficient. Rehearse on disposable roots under the intended account/filesystem: stop before and after exchange, parent sync and receipt; restart with partially closed or restored roots; reject a substituted sentinel, changed parent, extra sentinel entry, and a live holder of a parked descendant; exercise a module fallback and an unaffected pinned pilot route. Require successful reconciliation and a second independent read of all endpoint placements. Actual host inspection must also cover supported namespace and launcher settings. [Existing mount witness](/tmp/jsh-s4-site-verifier.NvDLJ7BT/alternate_writer_witness.py:49)

A root-managed read-only cover gives stronger resistance to deliberate removal by the launch account, at the cost of administrator and mount-lifecycle control. Both mechanisms require a drain and alias checks. The exchange leaves the parked directory accessible to its owner, who could deliberately reopen it or invoke its private path. Neither design establishes exclusive control over independent machines, human workbook edits or arbitrary direct clients. If any of those is an actual supported writer, it requires its own evidence or fence before release. No live checkout command, exchange, permission change, mount or service operation was tested in this review.
