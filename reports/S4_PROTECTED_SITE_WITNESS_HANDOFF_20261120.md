## Callable and trust boundary

Pass the result of `bind_host_witness(project, pin_file, pin_sha256, maintenance_id=policy.maintenance_id, verify_release_hold=owner_check)` as the third argument to `host_checkpoint.attest`. This returns its expected `protected(stage, target)` callable. Success returns True. Any failure raises WitnessHold with a bounded diagnostic, including when the owner check raises an exception. The helper checks the maintenance marker on held stages. Restoring permits either the exact still-present marker or its removal; preflight and restored require absence. The outer verifier owns the service, route and marker ownership proofs.

The site owner must independently authorize the expected logical baseline. The private 0600, single-link, current-UID pin file contains exactly `schema` = `protected-site-witness-v1`, the canonical absolute `project`, and `witness`. The last field has the shape returned by `measure_for_private_review(project)`, which contains only table/source/archive digests and presence indicators. Use already reviewed private evidence and a consistent authorized snapshot to enroll. The expected SHA-256 of the exact pin-file bytes must enter from the separately approved site policy. Never generate fresh expected pins at a checkpoint or substitute a pin-file self-hash. Bind this helper, all imported verifier files and pin-file digest in the controller's trusted tool inventory. There is no production pin file in this deliverable.

`owner_check(stage,target)` must return literal True only on independently verified automatic-release admission closure for that phase. The inspected release primitive acquires the canonical scraper lease. `verify_release_lease(project, authenticated_controller_pid)` checks the kernel's exclusive whole-file flock on the physical SQLite scraper lock by device/inode and owner PID, without opening the lock for writing or acquiring it. Authenticate the controller identity and process start time outside this helper. At stages before/after lease ownership, the site check needs the effective autonomous caller/policy hold. The source provides an activation primitive and an empty repair-profile registry; it has no universal SQLite automatic-release flag. An always-true callback would lose that part of the proof. The local witness also rejects a nonempty repair registry, pending repair intents, an unexpected release journal, enabled intake or active scheduler controls.

## What is protected

- Canonical State, Jobs, Inbox, retained session and wrapper coordinator databases must exist. Required ordinary tables are checked individually; an absent dispatcher, legacy start DB or exception DB is an explicit baseline state. A present DB missing its required tables or an orphan sidecar fails. Full ordered row-and-schema digests cover historical State/reviews, inventories, legacy recovery/provenance archives, frozen plans, cursors, chunks, exact local and remote receipts, retained sessions, outbox/acknowledgements, repair lineage and receiver evidence.
- The helper requires the unfinished historical CYC-B639C6D864EC and Saronic COMP-0054 membership, unique local Company and cycle mirror, saved inventory and plan. It checks the Samtec operator session receipt/intent/ack against the released local provenance and acknowledgement. It pins the original archive, consumption files, dirty/manual choices, conflicts, Job History human-review and salary fields with policies, and complete Opportunities rows. The independently accepted logical fingerprints establish the expected Saronic conflict and historical values.
- The local restart check requires queue/campaign/autopilot disabled, no pilot task, no queued/running/pausing task or open inference session, and only consistent terminal inference receipts. The legacy wrapper consumer must have no outstanding outcome to drain. The two receiver identities must have no pending transport attempt. Receipt-v1 accepted receipts must agree across sender and receiver with the sender's payload and local acknowledgement; local stale suppression needs no receiver. A receiver-only commit fails. The newer wrapper's default-off selected route and any environment-selected outcome ID remain outer host/source checks.
- All SQLite opens use URI mode=ro and query_only, with no migrations, checkpoints or writer constructors. With an absent/zero-length WAL and no hot rollback journal the helper uses immutable reads and checks main/WAL/journal identity and timestamps again. A nonempty WAL uses ordinary WAL-aware read-only SQLite and requires readable SHM and a non-writable view of the DB, WAL, SHM and directory so SQLite cannot create or update host sidecars. If those conditions fail, the checkpoint holds. An owner-provided genuinely read-only filesystem view or independently frozen private snapshot may support enrollment; a stale snapshot cannot establish live freshness. Cross-store consistency requires the outer writer closures.

## Acceptance limits

The fixtures covered historical cursor and manual-field drift, divergent Samtec ack, missing required schema, dispatcher appearance/enabling, active local inference owner, both delivery boundaries, held-marker replay, unsafe pins and filesystem paths, actual flock owner mismatch, and a committed WAL update. The WAL test simulated the read-only mount flag on disposable files and demonstrated that a committed WAL change was visible. No mount was attempted.

The local databases cannot certify an independently running Jetson operation without a matching MuleLab receipt. Remote device state and external launch closures need separate owner evidence. This witness compares pre-pilot maintenance state. An authorized pilot that changes protected records needs its own scoped readback. Full-table hashing cost and compatibility with the site's checkpoint deadline and actual WAL permissions remain unmeasured; timeouts or unreadable state must hold. No production checker, service, provider, workbook or remote device was invoked.
