## Findings

1. **Publication recovery replays the parked probe against a published package.** Injecting process exit immediately after the real atomic exchange leaves the controller journal at `PUBLISHING` and the canonical package fully updated. On rerun, `Controller.publish()` calls the documented parked `pre-publish` hook with the canonical directory. The strict fixture rejects it. The local `host_check.py` currently accepts either path at this checkpoint, and the controller test fixture does not enforce the parked checkpoint. This explains why a permissive controller test can pass the same crash. Distinguish the two sides of the atomic exchange on replay. When the correct terminal package is already canonical, verify the terminal receipt and manifest, make the observed exchange durable, and run the published recovery probe. Keep the service and journal holds through that verification.
2. **The external exclusion remains a prerequisite.** The same crash leaves the bootstrap routes blocked by the marker and the fully installed code directly importable. The rehearsal ran canonical direct help successfully after the crash and while the marker still existed. With the package parked, an interpreter that resolves the alternate checkout first still imports successfully. The supplied host checker snapshots process and service status, checks control state, and probes module behavior. It does not itself enforce a durable restriction on alternate environments, interactive writers, existing schedulers outside the held units, or source edits. Verify the actual inventoried closures on the host, including their crash and reboot persistence, before authorizing source mutation. A passed census is a point-in-time observation.
3. **Preflight evidence has limited scope.** The existing service-stage record shows sync inactive and disabled and intake flags false at its capture. Host process and scheduler coverage, all effective launcher environments, the accepted base prerequisites beyond the 13 exact scoped pins, and the current activation and policy state require host verification. The host launcher probe checks shell syntax and directly loads the selected runner. It does not exercise actual wrapper dispatch or the effective installed console path. The disposable tests exercised the real wrapper and bootstrap dispatch and their canonical direct routes.
