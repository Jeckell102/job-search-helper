# Sprint 4 joint release tools independent source QA

**HOLD the staged source gate on physical endpoint attestation and the host release checkpoint.** This is a pre-fixture source review of /tmp/jsh-s4-combined-release-tools.wkZs5rUo against the Sprint 3 tools and the joint release design.

## Source findings

1. **Physical identity is incomplete at endpoint and reopen boundaries.** The installer checks mount IDs for its named directory FDs, but the file reader validates regular type, link count, inode and change time without checking the opened endpoint's mount ID against its parent. An already matching endpoint on a per-file substitute mount can therefore satisfy receipt verification. The independent fixture simulated a different endpoint mount ID and confirmed verification never requested it. Separately, I renamed a disposable checkout ancestor and made the original path a symlink to the same moved tree. Reopen accepted the unchanged directory inodes and mount IDs even though the initial canonical-path validator rejected the new path. Enforce the physical route when reopening from the recorded path and check source endpoint FD mount identity for candidate reads, destination mutation checks and terminal receipt verification. Keep mount tests confined to the disposable fixture. [Endpoint read](/tmp/jsh-s4-combined-release-tools.wkZs5rUo/installer.py:191) · [Directory reopen](/tmp/jsh-s4-combined-release-tools.wkZs5rUo/installer.py:399) · [Terminal receipt](/tmp/jsh-s4-combined-release-tools.wkZs5rUo/controller.py:654)
2. **The release phase lacks an independently verified host checkpoint after restoring the wrapper.** Before release, the guarded and admitted probes use fresh nonces and exact reply echoes, with source and receipt checks on both sides. In RELEASING, the controller verifies the endpoint vector, removes or confirms absence of the marker, restores service state, and immediately records RELEASED. Both fresh and interrupted-release fixture paths did this without another host-check callback. Systemd's restore check verifies unit configuration and activity, but does not attest the active wrapper's process/checkout identity or protected stores. Add replay-compatible host attestation around restoration and verify the restored runtime and protected state before recording RELEASED. This needs its own source-level transition even after the separate site launch fence is implemented. [Host nonce contract](/tmp/jsh-s4-combined-release-tools.wkZs5rUo/controller.py:501) · [Unit restoration](/tmp/jsh-s4-combined-release-tools.wkZs5rUo/controller.py:422) · [Release replay](/tmp/jsh-s4-combined-release-tools.wkZs5rUo/controller.py:787)

## Verified source boundaries

- Root, package and the three exact wrapper endpoints now have distinct routing. The wrapper hierarchy is opened through no-follow directory FDs. Replacing the tools directory with a different inode was detected. All three existing wrapper endpoints are mandatory, and a fourth wrapper path was rejected. The installer verifies the canonical manifest SHA-256 and exact bytes, modes, owners and absences of its listed endpoints. Approval of the complete release-specific worker/root path set and its final manifest pin is separate evidence. The staged directory contains tools, rather than the final 47-endpoint manifest.
- The Sprint 4 schemas, parked basename, marker temp prefix and unit drop-in are distinct from Sprint 3. The runtime marker and shared locks retain their established names. The disposable transaction installed and rolled back the joint vector after the candidate was removed, restored a scoped absence, preserved the unrelated package file sharing a wrapper basename, and preserved both historical sentinel inodes.
- The installer persists before/after payloads and the active intent before replacing endpoints. Recovery reopens the bound directories, rejects third values, and fsyncs every affected destination parent including tools. Controller receipt reconstruction follows the same guard inode from canonical name to parked name during exchange and compares the exact terminal journal, receipt and source vector before guard removal.
- A targeted cache probe removed only the wrapper legacy, optimized and external-prefix bytecode and preserved the unrelated wrapper and same-basename package cache.

Eight targeted offline source and microfixture probes passed, including reproductions of the two findings. The probe blocked subprocess launch and socket connect, bind and lookup. The staged tree was imported with bytecode disabled and left untouched. Final manifest membership, end-to-end crash fixtures, package and wrapper origin checks with the actual interpreter, direct-launch closure, and the authenticated site launch fence remain distinct gates. No production paths, services, network or GitHub were used.
