A verified envelope plus that measured runtime determines the reservation digest and reserved run cycle. The claims do not contain the settled inventory, classification, or observed provider. ## Existing one-outcome procedure

1. After an independently authorized pilot fetch and settlement, read the exact archived event, consumed confirmed publication, and immutable Jobs outcome for the signed request and reservation. Pin the actual OUT ID, canonical record SHA-256, publication and settlement digests, and source/runtime binding in a separate owner approval for the delivery. Hold if the source is stale, the record is ambiguous, or publication is pending or zero for this pilot. The final pilot verifier requires delivery already present, so use the settled-event evidence for the pre-delivery selection and the full pilot verifier afterward. [Archived event and settled outcome](/tmp/jsh-s4-enrollment-release.EHxLVsCF/candidate/src/job_search_helper/retained_event_outcome.py:23) · [Terminal verifier](/tmp/jsh-s4-enrollment-release.EHxLVsCF/retained_pilot_terminal.py:46)
2. With explicit authorization for the service operation, apply a temporary environment overlay to the wrapper service alone, with `WRAPPER_SELECTED_OUTCOME_ID` equal to the verified ID. This check runs before the drain handler loads project `.env`. Project `.env` also contributes to the signed runtime config digest. Prove that queue, campaign and pilot controls are inactive and unresolved work has been reconciled before starting the wrapper with the overlay. Startup performs coordinator recovery and may claim enabled work even though broad outcome draining stays held. Recheck the same approved source and interpreter, expected unit and launch account, the new process identity and sole loopback listener, healthy supervision, and the exact scoped process setting. [Wrapper route and startup](/tmp/jsh-s4-enrollment-release.EHxLVsCF/candidate/dev/wrapper-coder/tools/host_server.py:142) · [Runtime config binding](/tmp/jsh-s4-enrollment-release.EHxLVsCF/candidate/release_admission_bootstrap.py:67) · [Coordinator startup behavior](/tmp/jsh-s4-receipt-candidate.i8gYgB0N/dev/wrapper-coder/tools/coordinator.py:635)
3. Use the existing authenticated loopback `/coordinator` request whose only fields are `action=drain-selected-scrape-outcome` and the approved `outcome_id`. The host keeps the writer lease and normal lifecycle guard. The bridge selects only that Jobs row and calls the fixed in-process `ingest-scrape-outcome-delivery-v1` action. The receiver pins the immutable record and atomically freezes its receipt. The sender checks the returned receipt, atomically records it and its acknowledgement, and clears that outcome's attempted delivery state. Direct intake over HTTP and unselected catch-up hold. The staged host and the earlier receipt fixture host source are byte-identical, and the fixture checks that an unrelated outcome remains pending. 4. Independently reread both ledgers under the approved verification procedure. Require sender `ACCEPTED` with acknowledgement, receiver exact intake and one receipt, identical receipt hash and record hash, the same `repair-coordinator` consumer and `ODR-` receipt ID, and `RECORDED_NO_REPAIR`. Confirm unrelated outcome and delivery records are unchanged across the controlled window. An empty reply after an authorized replay is ambiguous without the ledgers; an interrupted delivery must respect the existing reservation and retry state. Remove the temporary overlay after proof. An already running process retains its inherited setting, so verify capability removal on a same-source controlled replacement process that starts without the setting. Repeat process, listener, service-health and unrelated-ledger checks after that start. If either controlled start cannot be authorized and kept quiescent, the smallest reviewed source change is a single expiring owner-approved selector read by the same authenticated host route. A protected owner-controlled runtime file can contain one ID, canonical record and settlement digests, exact request/event/reservation and source/runtime binding, and expiry. Validate those values under the existing lock against the archived consumed publication and immutable row before invoking the unchanged bridge. This needs a reviewed deployment once; later selections can be armed and removed without restarting the wrapper. It requires its own owner authority for each selection.

This is staged source evidence and a proposed operating procedure. It establishes no live fetch signature, owner service approval, runtime observation, or delivery receipt. No systemd, service, production database, or network access was used in this review.
