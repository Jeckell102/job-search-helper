## Continuous hold and recovery

1. Before any endpoint mutation, establish the persistent unit holds and drain wrapper/sync cgroups, listeners, children, and in-flight receiver/worker activity. Acquire existing install → scraper → writer → review ownership, with separate controller and installer locks, and verify any other actual publisher controls. The site verifier must establish an enforceable closure for direct wrapper scripts, console/alternative checkouts and independent same-store writers that survives controller death and user-manager restart. A process census only observes an instant. The scraper import guard cannot close a directly launched wrapper: the host can bind its socket and start coordinator supervision before lazy scraper imports. If any such route remains launchable, hold the release until its owner provides a persistent launch fence. [Host startup](/tmp/jsh-s4-dispatch-binding-qa.i45G33KN/dev/wrapper-coder/tools/host_server.py:263)
2. Under the continuing hold, capture and fsync **all** before/after payloads and explicit absences, then persist INSTALLING before the first rename. Reuse the existing per-path attestation and atomic replacement. After a crash, verify the exact host, bindings, hold and fixed endpoint identities, and accept only recorded before/after values while converging in the journaled direction. Reject third values. Preserve the installer's candidate-independent rollback. Purge only the affected caches under canonical/parked package, root and actual wrapper tools paths, including legacy, optimized and external-prefix bytecode.
3. Require a single terminal installer receipt for the whole endpoint vector before package exchange. Verify it again at parked pre-publication, canonical guarded publication and admission-ready replay. Reconcile exchange by inode and fsync before advancing. Verify the complete target after guard removal while marker and units still hold. Prove worker and wrapper origins, including lazy bridge/store resolution, with the effective service interpreter and credential-free isolated dependencies. Use fixture state for import/behavior probes: importing the actual host module reads its bridge token, and its main starts a listener. Test selected receipt-v1 and duplicate delivery, held broad catch-up and denied direct intake on the new target.
4. The controller alone restores admissions. Persist the direction and verified joint result before removing a marker or unit hold. A crash during release may expose an already verified matching pair. Recheck that pair before completing restoration, reconcile each drop-in, reload, sentinel and prior service state idempotently, and verify the restored wrapper's process/checkout identity plus protected state. Keep sync disabled/inactive with its prior expiry. If rollback is requested after reopening, reacquire and re-prove the full closure before changing either side. Verify all old endpoints/absences, cache selection and the **old** pair before restoring availability. Old broad supervision catch-up can act immediately: an in-flight claim, receipt, publication, or pending backlog incompatible with that behavior requires disposition while the wrapper remains held. Source rollback cannot undo external work.

## Independent acceptance

Kill the disposable controller/installer around the first and last wrapper rename, a package replacement with wrapper bytes already changed, final rename before parent fsync, terminal receipt, package exchange before phase save, guard unlink, and each unit-restoration edge. Exercise both resume and rollback, including candidate removal, repeated commands, manager restart and stale bytecode. In each mixed state, attempt the supported direct and supervised receiver/worker routes and prove refusal before listener, store constructor, provider or delivery. At release verify only the complete target pairing can run. Inject a replaced parent, wrong owner/digest, mismatched tool/version, occupied historical namespace and missing hold. Witness scoped/untouched identities, protected SQLite and work records, control states and receipt equality. The previous stub-based rehearsal does not establish host exclusivity.

A wrapper subtransaction is justified only if a genuinely separate mount/owner demands it. It would need a parent-journaled child identity and intent **before** child mutation, durable two-sided payloads, verifiable child terminal receipts in both directions, and parent-only authority to publish, restore or roll back. It still needs the same persistent route closure. On the proposed single-mount checkout it adds a cross-journal crash boundary without reducing the host trust requirement. Proceed with the single-journal extension for a new disposable rehearsal. Live readiness remains unverified.
