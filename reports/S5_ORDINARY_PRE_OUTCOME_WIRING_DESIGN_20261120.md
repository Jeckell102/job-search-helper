## Sequence for the first implementation

1. Limit the first slice to one ordinary single-Company request with one exact reviewed Rippling qualification and no earlier outcome. Bind the marker to cycle ID and start time, request ID/fingerprint, Company ID and frozen source revision, installed capability/mapping/configuration and qualification matrix, measured runtime and exact observation generation. Exclude event, retained, recovery and retry ownership for this slice. Before probing, preserve existing stale/paused, known storage failure, complete/verified zero, access and transient outcomes.
2. Pre-arm the exact cycle item during assignment. Save the compact mismatch marker at the normal incomplete checkpoint and let the worker finish its existing storage work. A crash between inbox save and the State companion write leaves the exact item pre-armed. Resume using the marker when present. If the typed observation was never committed, either reobserve just the same configured endpoint while the same frozen admission is still current, or retain a visible pending hold. Human-readable reason remains ordinary context. Retain ordinary final drain and check its local verified publication record before creating a qualified result.
3. The verifier snapshots the exact pending record and closes all read handles before public I/O. It holds neither cooperative runtime lock while working. Use a finite total deadline, request/detail budget and cancellation for the reused reader. The default shared client can retry requests, paginate extensively and expand details, so its existing per-request timeout does not bound this phase. Budget exhaustion, ambiguity, stale inputs or missing full-detail/final-reread proof yield an explicit nonqualifying disposition. Record the verifier receipt under a private owned channel with the exact pending identity, verifier version and digest of canonical observed evidence. Raw captures remain private and follow the reviewed evidence-retention rules. A caller-supplied fact or a trio of digest-shaped strings has no route into custody.
4. Resume through the launcher and use one new measured scraper admission for this local continuation. Revalidate its still-open descriptor and current installed runtime and compare to the frozen pending record. Acquire the existing writer lease once for the short phase. The previous admission is intentionally over during external verification. Recheck physical State/Jobs identity, exact workbook/Company row, publisher confirmation and original outcome history with fresh private handles. Commit the owned receipt with `persist_runtime_mapping_fact`, reread by fact ID, then seal the existing checkpoint group. Reread State and call the existing sealed Jobs outcome writer while the same two local leases remain active. A verified result reaches the first `QUALIFIED_INTEGRATION_REPAIR` outcome only after storage and current-source precedence passes. Absent/changed evidence stays a hold or resolves to the existing appropriate terminal outcome once the owned verifier gives a terminal negative.
5. Keep the original attempt identity through every retry of this continuation. Crash before fact persistence resumes the same pending record. Crash after fact persistence reuses identical fact ID, after sealing reuses all three identical fields, and after outcome commit reconciles the exact immutable row before clearing pending. Return a prior terminal unknown unchanged before any new fact/checkpoint admission. Snapshot drift while paused invalidates the receipt, preserves prior observations and lets normal stale/paused precedence win where applicable.

The existing worker writes outcomes before its final remote drain. For the enrolled case, separate “publication still pending” from a terminal storage failure, and use verified local readback after the ordinary drain or on a later exact continuation. This keeps the positive slice possible without holding `writer.lock` across remote synchronization or using a fixture's synchronous fake drain as the runtime contract.
