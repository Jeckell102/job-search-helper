# Native administrator process observation for Sprint 4

The last live rehearsal left a specific process-attribution hold.
This staged change lets the release verifier ask a native administrator
terminal for current read-only route evidence about exactly the two
supported system programs `ssh-agent` and `(sd-pam)`. The approved
durable release policy must bind the observer socket and the complete
route inventory. The observer validates the selected UID and PIDs,
checks the actual executable object against the operating system's
program and reads the current process references for each challenge.
Outputs contain only process fingerprints, no raw command lines or
open paths. The site still rejects any checkout reference it can see.

The observer is a foreground process with a bounded lifetime on a
root-owned local Unix socket. It checks the launch account by kernel
peer credentials, while the release verifier requires a root peer.
Every missing, switched, late or mismatched response holds the
checkpoint. Each request is nonce-bound and enforces its elapsed-time
deadline. There is no persistent daemon to install. Start a fresh
observer when the owner window is established or the selected process
identity changes. A session release is separately required for the
old Codex tool workers. They cannot use this system-helper route.
