The controller returned with the canonical script present, the phase still HOST_REOPEN and no direct-path re-hold attempt. The reopen operation runs before the release recovery handler. The controller needs to re-establish canonical absence if a validation or journal transition fails after the host name is recreated. In a separate RELEASE_REFUSED replay, interruption inside service re-hold left the canonical host present because direct-path closure runs last. Attempt an independently pinned direct-path closure despite journal-write failure, and put it before the potentially long unit-restoration steps. Retain the refusal and closure errors for recovery. [Refusal write before closure](/tmp/jsh-s4-combined-host-fence.Csm9gwcg/controller.py:907) · [Closure order](/tmp/jsh-s4-combined-host-fence.Csm9gwcg/controller.py:858)

The action gate rejects rollback from both that phase and RELEASE_REFUSED and requires completion of the original install release. A host that repeatedly fails restoration cannot use the available sealed old image and candidate-independent rollback without first accepting the failed target. Allow an explicit rollback after proving full re-hold, without demanding successful forward release.
