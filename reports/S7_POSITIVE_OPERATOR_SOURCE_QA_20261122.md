# Positive operator company-only entry

November 22, 2026 Eastern. The existing operator queue could reserve one
Company, but only narrow failure commands or genuine workbook events
could run without the broad Start lifecycle. The new explicit command
runs a reserved `operator-company:` ID under stable scraper admission
and the ordinary writer lock. It keeps the durable operator request,
one Company and its actual release as publication authority.

`admit-fetch` verifies the current Company and its workbook source,
then claims and freezes one normally dispatched observation. Reopening
a frozen observation does not call the provider again. `publish`
requires the exact cycle, completes ordinary filtering through the
existing exact planner, and publishes only frozen identities. It retains
the recorded provider result when publication is uncertain and recovers
by workbook readback. Nonpositive inventories and uncertain provider
claims remain held. They do not receive positive publication credit.

The initial composed test found the Inbox was expecting a cycle ID as
the request identity. The exact v2 receipt/plan now carry the real
operator ID, source revision and active installation. The initial
independent read-only review also held the candidate for a restart gap
between State, cycle mirror and Company membership, and for a missing
current-name comparison. The repair reconstructs only the same queued
membership/mirror when no competing work exists, and binds the display
name to its saved admission. The workbook Company guard now runs before
new Inbox staging.

Final independent source QA accepted the exact candidate. Four focused
fixtures passed, covering real bootstrap dispatch against disposable
stores, early admission restart, request/Company drift before provider,

suites passed 58/64. The same six fixture errors reproduced on
