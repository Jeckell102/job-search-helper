# Sprint 4 retained-pilot restoration command

November 20, 2026. The staged command in
`/tmp/jsh-s4-restoration-command.UmldUtdW` has two distinct operations.
Observe uses the existing release leases and read-only evidence paths
to emit the exact proposed restoration record. Restore requires a
separately approved digest of those private bytes, and reopens the
alternate routes only when the release, closed exchange and freshly
read two-sided pilot settlement still match.

The independently pinned selection names the exact project interpreter,
workbook digest, receiver database, exchange policy, tool files and
selected event/reservation. It is itself included by digest in the
proposed restoration. The command executes the verified bytes of the
private bundle modules, requires the same effective virtual environment
the normal bootstrap measures, and checks both configured SQLite file
identities before and after the application read. It requires the
existing released controller in the same private, approved bundle and
source tree used for the release. It cannot be retrofitted into another
controller journal. The release owner must verify the command itself
and the full selection out of band before execution.

## Guarded invocation

`-I -B -X pycache_prefix=/dev/null`. Invoke
`pilot_restore_command.py observe --selection PATH --selection-sha256 DIGEST`
and keep its stdout in a fresh private mode-0600 file. The owner or
approved independent verifier must independently validate the selection,
host custody and actual settlement before accepting the resulting hash.
Invoke `restore` with the same selection and add
`--approval PATH --approval-sha256 DIGEST` for the independently approved
observation. Preserve both exact private files for replay. No credentials,
raw jobs or live receipt files belong in the GitHub backup.
