# Site checkpoint source QA repairs and policy bundle format

November 20, 2026. Source-only repaired candidate at
`/tmp/jsh-s4-site-verifier-repair.PoeeKDWI`. Independent QA held the
previous checker because its drain rejected the real release processes,
it did not repeat listener and process checks after protected-state
verification, and the service invocation omitted empty requested
fields. Additional findings covered permissive checkpoint spelling
and an active wrapper accepted while its maintenance marker remained.

The repaired checker authenticates the exact isolated controller,
installer and verifier process ancestry, stable process identity and
kernel lock ownership. It permits only fixed approved checkout
references from those authenticated processes. It repeats the listener
and route census before replying, requires the same network namespace
and listener inode vector, and rejects a shared listener inode within
the configured launch account. It explicitly requests all unit fields
and captures service stderr. Held labels and package paths must be
literal, and a running restoring wrapper cannot have a marker present.

protected witness module and approved policy in the single executable
the release controller pins. A fixture proved that execution uses
bundled code with an unrelated PYTHONPATH and rejects replacement of an
existing checker. Fifteen disposable tests passed. The actual private
policy, protected state module, phase-specific real launcher probes,
integration of the runnable verifier, and exact site evidence are still
pending. No production services, files, covers, job data or Jetson
state were changed.
