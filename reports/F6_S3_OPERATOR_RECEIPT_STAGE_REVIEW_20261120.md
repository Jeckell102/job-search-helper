# Sprint 3 retained receipt source audit

The roadmap requires three receipt proofs bound to the exact request, Company, source revision, release, and record identities. The staged v2 retained path supplies durable evidence for all three through the admission journal, retained Session, and Jobs provenance. Its operator response exposes only terminal `SYNC_CONFIRMED`. The shared receipt module supports a named `LOCAL_COMMITTED` receipt, but the retained path imports its fingerprint helper only. `exact_local_plan.LOCAL_COMMITTED` is a compatibility alias for `VERIFIED`. A proof package should label the joined local evidence explicitly. A requirement for the operator itself to issue three named receipt artifacts remains unimplemented. ## Evidence by stage

| Stage | Durable evidence and interpretation |
|---|---|
| `LOCAL_COMMITTED` | The signed reservation has a frozen Session and plan. Jobs `exact_local_applications` is `VERIFIED` with `verified_at`, and its contiguous `VERIFIED` chunks cover every planned local operation. Jobs provenance separately seals `LOCAL_VERIFIED` with `local_apply_id`, `cells_digest`, and `local_verified_at`. A prepublication capture has Session `RESERVED`, null receipt/intent/acknowledgement, cursor zero, and no remote chunks or local acknowledgement. A crash after application `VERIFIED` and before provenance sealing still requires provenance replay. An `APPLIED` chunk is a durable recoverable write boundary on its own. |
| `SYNC_PENDING` | Session freezes `receipt_id`, `intent_id`, `exact_scope`, and `exact_scope_digest` for the plan projection. Jobs provenance then binds the same receipt/intent and projection at `REMOTE_PENDING`. A crash between those transitions leaves Session pending and Jobs `LOCAL_VERIFIED`; binding can resume before dispatch. A `CLAIMED` chunk durably identifies an attempted range, and its presence alone establishes neither dispatch nor delivery. The remote cursor represents the contiguous confirmed prefix. |
| `SYNC_CONFIRMED` | Full exact selected Sheets readback produces the Session acknowledgement and confirmed remote chunks. The matching Jobs acknowledgement records `selected_fields_digest`, advances the baseline and clears the selected dirty cells, and provenance reaches `REMOTE_CONFIRMED`. Session can reach `SYNC_CONFIRMED` before that Jobs acknowledgement commits. The operator's public terminal result further requires `FIRST_PASS_RELEASED`, validates the exact queue artifact and matching local application/acknowledgement, then settles and consumes the matching request. |
