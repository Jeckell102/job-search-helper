# Sprint 5 automated release pre-install guard

The isolated automated entry point reopens a qualification receipt through its configured private directory and checks the separately approved exact file hash. Qualification requires the closed live normal-dispatch receipt schema, an explicit PASS and release eligibility, the exact canonical release manifest and the validating receipt digest. Saved-capture, synthetic or public-only verifier output cannot enter the installer. The current staged code has no production qualification producer configured. [Design review](S5_PREINSTALL_QUALIFICATION_REVIEW_20261120.md)

The existing scraper lease still controls installation and completed release readback. Before creating a rollback backup, the automatic route measures the complete qualified candidate and verifies that the proposed writes would produce the complete installed source and configuration hashes. It then rereads the pinned qualification inside that lease. A withdrawn receipt, drifted candidate, or an omitted source file holds before release backup or journal creation. Legacy manual callers continue through the same existing installer and post-install verification. When the optional capture directory is configured, the installer and measured bootstrap now include the same configuration pin.

Before writing COMPLETE, the installer records a digest of the entire release receipt in its terminal journal. Automated restart requires this pin and validates release, failed request, company, revision, activation time and canonical installed verification. A changed receipt cannot advance to retry scheduling. Existing manual releases created under the earlier journal format still read back when their original static identity matches.

The 76 focused release tests and 530 combined tests passed with Python 3.11.18. Independent QA accepted the staged slice after rerunning the 76 tests and adding 10 independent cases. The disposable positive case stages a single exact retry after fixture qualification and guarded install, and reuses it after an interruption. Rejected cases leave existing data, files, release backups and retry state unchanged within the tested scope. No live capture, production deployment, workbook write or Jetson work occurred. The administrator observer is still unavailable.
