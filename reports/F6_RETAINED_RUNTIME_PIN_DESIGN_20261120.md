# Sprint 3 F6 retained receipt runtime binding

**Source finding.** The installed retained Company command omits the F3 runtime identity from the durable receipt chain. A settled release journal is only one prerequisite. To satisfy F6, measure the runtime under pre-import admission and link it to each retained reservation's exact local verification, pending intent, and confirmed readback. The existing receipt chain can carry that identity without new SQLite columns or changes to the historical cycle.

## Recovery policy

| Persisted evidence | Safe behavior |
| --- | --- |
| Pinned frozen or pending work and exact current pin | Validate all stored identities before factories, reopen the saved inventory and plan, and continue with the recorded local/chunk cursor. An existing `CLAIMED` remote chunk uses its persisted count and exact scope and is readback-only. The current implementation derives the count from the CLI limit and rejects a changed bound. Either resume with the original bound or explicitly recover the persisted claim before applying a new bound to an unclaimed suffix. Missing, changed or ambiguous readback keeps the claim. No new provider call or second send occurs across a lost write acknowledgement. |
| Pinned admission/intake hold with missing or empty start journal | Probe the request, exact admission, intake hold and existing session/publication before the first provider invocation. The current two-store freeze can crash after creating admission or the intake hold and before saving the inventory. Reuse matching sealed durable evidence when present. Hold and diagnose an incomplete handoff. Do not infer the inventory or create a second reservation. If a terminal publication already exists and the journal was deleted before the archive was written, verify that exact request and its entire terminal chain, then finish only consumption while locked. An archive is not the only locator for this terminal gap. |
| Pinned receipt with a missing, changed or unverifiable runtime | Keep the exact request, embargo, dirty scope, cursor and claim. Reacquire admission under the same source/config/dependency and release identity to resume. A new release or rollback ID is a different pin even when one tree digest matches. A new active release cannot grant permission to re-key saved work. |
| Legacy unpinned admission, frozen start, local commit, pending claim, or incomplete confirmation | Distinguish explicit legacy format from a corrupt new payload. Report a dedicated legacy hold before factories, fetch, exact write or record mutation. Preserve original IDs, embargoes, plans and claims. Use read-only diagnosis to classify known local progress and any retained remote claim. Any separate operator reconciliation must use the old exact evidence and proved delivery state. Preserve the original pin status, ambiguous claim, and historical cycle. |
| Legacy fully released terminal evidence | Leave completed consumption evidence unchanged. If an exact archive/request still needs cleanup, permit only a bounded local consumption repair after independently validating admission and provenance, confirmed private session and local acknowledgement, the exact released publication and queue file seals. Preserve any replacement request. That cleanup retains the historical unpinned classification and does not create a new F6 receipt. Otherwise leave it held. |

Protect the historical State/inventory/job evidence throughout. The existing exception signature remains necessary and separate from the runtime pin. The installed raw blocker-count and overlap restrictions identified by the admission audit still apply. The retained entry also constructs `State(readonly=True)` with the default `:memory:` argument, which the current State implementation converts to a filesystem URI in read-only mode. A composed fixture needs the explicit existing read-only State handle, or the same actual State path, to reach the orchestration boundary.
