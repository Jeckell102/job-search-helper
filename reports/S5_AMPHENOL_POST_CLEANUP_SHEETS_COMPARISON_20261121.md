# Exact repair receipt workbook comparison after cleanup

The existing terminal receipt and Jobs apply journal are enough to prove fresh workbook values against the original receipt for a plain-field publication. No plan regeneration is required. The retained evidence cannot reconstruct the original complete write intent or every append-note projection.

## Retained evidence and exact scope

- Join the exact State retry (its one `company-retry:<RTRY>` request, Company, source revision and release) to its Inbox `SYNC_CONFIRMED` publication receipt and one Jobs `VERIFIED` `exact_local_applications` row with a matching `exact_local_acknowledgements(receipt_id, acknowledgement_id)` row. The receipt's `records` maps `tab + ':' + canonical JSON(final identity)` to its SHA-256 fingerprint. Use the exact application `row_scope` list for each final `tab`, `identity`, local `row_id`, published `fields`, remote `expected` values and local `guards`. Require a one-to-one match between receipt record labels and verified scope. Resolve local row IDs through a unique exact identity before reading current baseline; row IDs are local hints, never worksheet coordinates.
- Correction to the earlier general procedure. The enrolled `compact-v1` workbook publishes only Companies, Job History and Opportunities. Scan Cycles, Job History Source Hash, Decision and full description are local evidence. Scope from the receipt governs actual tabs, which need not include all three. A nonpublished guard is not a missing workbook cell. A frozen `expected` value can be the old value for a touched field. Do not compare that old value to the finished row.
- Ordinary released retry cleanup removes the saved inventory, sync plan, exact remote plan and chunks. The selected-temporary and ordinary Company-event archive branches do not recognize its binding. The local application and acknowledgement retain digests; `selected_fields_digest` is the hash of the original readback rows, not their stored values. An existing exact-local chunk retains pre-apply records and hashes, not the complete remote operation or note-suffix authority. A current Jobs `baseline(tab,row_id)` does contain the observed outgoing fields written at acknowledgement, but later legitimate synchronization can update it.

## Smallest read-only comparison

Use an already-authorized read-only workbook handle bound to the same unique Inbox destination. On each scoped tab, call existing `GoogleRepository.read_columns` for the union of selected identity columns only. Use repository identity equivalence to require exactly one row for each key. Call `read_rows` for only those matches and revalidate the identity in every returned row. An enrolled reader may instead fetch only those cells with the same value representation. Require all selected headers, preserving values and blank representation without coercing the live field values used in a digest. The normal application's `get_remote_repository(write=False)` can still persist a refreshed token and is unsuitable when no local writes are allowed.

For the fresh -06 ordinary repair path, `_seal_exact_plan_v2` emits this publication with default v1 **record fingerprint** semantics. This is distinct from its v2 **plan** format. For each retained scope record form a comparison-only entry with its exact final `identity`, `tab`, `values` limited to the retained `fields`, and empty `append_notes`. Compute `publication_receipts.record_fingerprints(entries)` using the current acknowledged baseline fields, and separately using freshly observed Sheets fields. Compare each full map to the durable original receipt's `records`. Require exact agreement before claiming verified plain-field receipt coverage. An equal historical hash binds the scoped values even though the present baseline is mutable. Conventional value equivalence remains useful for identity/guard checks and for diagnosing any mismatch, but does not replace digest equality. No publish, confirmation, acknowledgement, or remote writer call is involved.

There is no need to assume a row was a plain overwrite just because a text field is present. The empty-note comparison is admissible only when it reproduces that row's original receipt hash. An actual append-note suffix typically yields a different hash because it was hashed separately from scalar values. If either map differs, report exactly which rows lack reproduced proof (and current workbook-vs-baseline agreement if separately supported). Do not derive a suffix from current text or fabricate a historical acknowledgement. If an authenticated, complete frozen remote plan and intent were separately retained, reuse existing `SheetsSynchronizer.readback_exact_scope` for the original operation, guard and optional note semantics. That method differs from `confirm_exact_scope` and `confirm_and_acknowledge_exact_scope`, which write state.

An immutable, query-only read of an existing completed disposable operator-repair fixture confirmed one canonical retry receipt, matching labels, one Companies row and one Job History row, and both no-note baseline fingerprints equal their original receipt. No production store, workbook, provider or service was contacted for this design review.
