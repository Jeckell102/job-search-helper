# Sprint 4 retained Company-event fetch settlement

A returned provider result and a lost request are different cases. Keep
FETCH_CLAIMED as the uncertainty hold when the provider does not return or
the process dies before committing a response. A duplicate invocation must
never infer a retry from elapsed time. An exact typed provider response can be
frozen before any downstream action. Store the validated structured failure
only in the event admission archive. Keep the ordinary operator's frozen
inventory and all exact publication identities compatible.

For the event action, bind a returned snapshot to the exact requested URL,
Company and resolved provider/board. Reuse ATS machine codes for access and
transient evidence. An unqualified provider or an unclassified failure remains
an engineering or operator hold. Preserve partial jobs as bounded local
evidence and never run absence-based status changes or advance a complete-check
stamp from them. Ordinary retention and complete operator copies retain their
current validation and publication rules.

An exact failed-fetch terminal record needs the original request hash,
reservation, frozen result hash, stable cycle/outcome identity and durable
outbox proof. Record the classified outcome under the same ownership before
consuming its request. Give its request-consumption receipt a distinct state
from FIRST_PASS_RELEASED_CONSUMED. If the process dies before the outbox write,
reclassify only from the frozen result. If it dies after the outbox write, read
the exact persisted outcome, verify it and consume once. If it dies after
archive/unlink or after creating the consumption receipt, compare exact
digests and preserve any replacement pending bytes. An alternate signature or
runtime cannot create another attempt for an already admitted request.

A completed fetch with unsettled storage is still owned by the exact
publisher. Reconcile only that publication. Do not send it to integration
repair. An explicit verified zero is a successful fetch and needs a
durable no-work or empty-publication proof. An empty partial/error snapshot or
empty scrape due to a weak selector is insufficient. Stale or removed
source should result in a durable cancellation before any later publish or
install. Source changes after local commit should hold the exact original
publication for safe reconciliation rather than erase it.

Keep the manual dispatcher hold and historical F5 conflict active. For real
evidence, pick a bounded currently eligible disjoint Company. The acceptance
matrix also needs supported idle and busy event delivery, realistic failure
classification on ordinary and scoped routes, duplicate delivery/restarts,
one exact receiver receipt and one correctly routed retry, hold or repair.
