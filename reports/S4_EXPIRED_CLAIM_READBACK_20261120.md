# Sprint 4 retained claim readback after expiry

The disposable candidate adds `recover_claimed_retained_chunk(reservation_digest, store, local, remote_reader, *, claim_id, runtime_binding)`. It validates the exact bound retained-v2 runtime, reservation, sealed plan and published local intent, and re-derives the stored claim's ID and operation digest from the frozen projection. It uses a read-only jobs connection and lazily opens the reader only for the one existing `CLAIMED` slice at the durable cursor. Its sole workflow write confirms that same claim in the existing retained session store. The helper never calls the claim allocator or the remote commit path. An exact retry after a committed confirmation returns the stored proof without opening the reader. [Helper](/tmp/jsh-s4-claimed-readback/source/src/job_search_helper/retained_work_publication.py:142)

## Results and ownership

- `HELD_UNCLAIMED_SUFFIX` means the exact named chunk was confirmed and the remaining projection is unclaimed. The session remains `SYNC_PENDING`; no suffix claim or batch exists.
- `READY_FOR_FULL_READBACK` means the exact named chunk was confirmed and the contiguous confirmed prefix now covers the sealed projection. The session still remains `SYNC_PENDING`; there is no global acknowledgement or publication settlement.
- A missing or ambiguous exact remote value leaves the stored claim and cursor unchanged. A foreign claim, modified operation digest, substituted reservation, or different runtime stops before the remote reader factory. A lost caller response after confirmation can replay the same claim ID without a second readback.

The caller owns the inherited scraper lease and `writer.lock`. The helper takes the existing private publisher lock. Only the reservation-addressed session store may be writable. The return includes reservation, claim, original slice, receipt and intent IDs, recorded readback digest, cursor, session state and unclaimed operation count.

## Integration contract

1. Route the specifically verified expiry case to this branch before fresh Company preflight, fetch, local plan application, writable jobs factories or any remote writer. Parse the signed expiry and cryptographically verify the same original envelope against current trusted verification material. The existing internal verifier supports signature checking independent of expiry through `require_unexpired=False`; expose this only in the exact recovery branch, and still require the timestamp to be valid and expired. Derive the existing binding with `operator_journal_binding` and compare it with the active frozen journal, including the original envelope authorization digest, key, signed claims, runtime and reservation. Hold any replacement signature or different returned binding. Do not use a new signature to prepare another reservation for this request. [Signature primitive](/tmp/jsh-s4-claimed-readback/source/src/job_search_helper/selected_recovery_authorization.py:160) · [Original binding](/tmp/jsh-s4-claimed-readback/source/src/job_search_helper/retained_operator_journal.py:72)
2. Under the two caller leases, inspect the existing session for that reservation and original signed identity. Require its remotely pending frozen intent and the exact existing outstanding claim at its durable cursor, or the last confirmed claim for an explicitly pinned response replay. Supply that stored claim ID to the helper and use a Sheets reader factory with no write capability. Hold a pending session without an existing eligible claim. Return `HELD_UNCLAIMED_SUFFIX` directly when the result names a suffix. An already archived or settled original reservation belongs to the existing terminal-evidence replay path.
3. If the result is `READY_FOR_FULL_READBACK`, a separate terminal-only path can verify the full sealed projection with exact Sheets reads and confirm full readback after rechecking the complete contiguous claims. This crosses the next durable boundary. Completing publication then requires local dirty acknowledgement, retained provenance confirmation, first-pass release and exact session settlement before the outer journal can record settlement and consume the original queue request. The original queue, jobs store acknowledgement and first-pass release deliberately stay outside this helper. Do not call the normal publisher on expired authority to reach these steps. Its loop can create a fresh claim, and its setup can freeze intent. Explicitly support crash replay between full session confirmation and local/first-pass terminal evidence; the current outer terminal shortcut assumes evidence already exists when it sees a confirmed session. ## Offline verification

The fixture uses real disposable SQLite and an in-process workbook. It applies one synthetic batch, loses the response, and confirms the original claim through a transport interface that only supports reads. It checks the one-operation suffix and final-claim cases, original receipt/intent/claim IDs, replay without another reader call, and no changes to the jobs store, queue, full session acknowledgement, or first-pass state. It also covers unapplied claims, a missing claim, frozen-claim corruption, a substituted reservation and runtime drift. It does not call signature issuance, a provider or Google. The parent-owned signed-entry integration and terminal-only continuation remain separate.
