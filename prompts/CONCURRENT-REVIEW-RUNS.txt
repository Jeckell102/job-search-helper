THREE-PASS REVIEW LAUNCH GUIDE — three-pass-concurrent-v1 / multi-run-v2

SHARED REFRESH AND LIVE-CHECK OPTIMIZATION — 2026-10-21
Normal startup still performs a fresh Sheet control read. In SQLite mode it may then reuse a verified published queue when source revisions, policy files, inventory file state and queue hashes still match. Concurrent starters share one rebuild instead of rebuilding once per worker. Direct-Sheets mode and databases without revision tracking do not take this shortcut. Explicit refresh, finish and manual-reopen recovery still force a fresh build.
Rebuilds prepare a consistent local read snapshot under a separate builder lock; the publication lock is held only for final validation and file replacement. Existing reviewers can read the previous verified queue while a replacement is prepared. If relevant inputs change during the build, publication is refused and the previous queue is preserved; retry rather than claiming completion. New/changed source evidence, newly eligible history, policy changes and inventory changes invalidate startup reuse. Completed-review removals are enforced immediately by live controls without requiring all remaining descriptions to be rescored.
Live control columns are fetched on EVERY normal command as before. Only redundant local merge/selection processing can be skipped when that fresh remote response and the transactional local revision both match the last successful reconciliation. Manual No/Yes/Manual Review/blank changes, Pending reopens, local review updates and failed reads retain their existing protections. There is no remote-data TTL and no background watcher.
queue_refresh reports reuse, build time, builder-lock wait, publication-lock time and total refresh time. sheet_controls.local_processing_skipped reports the local shortcut, not a skipped Sheet read. These metrics measure controller overhead, not model review throughput. Selective final review and exact-claim submission rules are unchanged.

LIVE SHEET CONTROLS — USER UPDATE 2026-10-21
Normal review is limited to jobs present in the working Job History sheet. Local-only title-audit records remain preserved but are excluded from the active review queue; do not review or silently import them. A separate future audit requires explicit user scope.
Normal start/next/submit/status/heartbeat/finish/writeback commands now import live Job Key, Added to Opportunities?, and Review Notes before acting. Changes to No, Yes, Manual Review, or blank remove a job from review even when Review Status still says Needs Review. A manual change back to Pending requests fresh description review; prior decisions and delivery intent are retained in the audit history. Removed sheet rows are excluded without deleting local history.
The controller cancels affected live claims and reports skipped_manual on submission, while saving unaffected jobs. Do not count a manually skipped job as newly reviewed. A failed live control read blocks new claims/submissions; do not bypass it with --local-only during a normal live run. Continue renewing through heartbeat while a long assessment is active. Changes are observed on these command boundaries, not by an unattended background watcher.
Use ./job-search-reviewer controls for an immediate import/reconciliation without starting a review. This command does not publish to Sheets. In SQLite mode, normal submit, writeback, and finish save to the local repository and then automatically publish the saved review and required Opportunity through the guarded Sheets publisher, even when the scraper is stopped. Inspect publication separately from local writeback: Saved Locally is not a Google Sheets delivery receipt. Only a verified remote publication counts as a Sheet update. Pending publication must be retried and reported as unfinished delivery.
These live-control and visibility rules supersede conflicting audit-routing or Written/Sheet wording below and in older prompt copies.

FIRST PASS: low-cost title sanity/rescue. Return RESCUE or PASS without reading descriptions. Normal submit automatically synchronizes saved PASS through the guarded helper as title-screened Added to Opportunities? = No. RESCUE hands off to SECOND PASS without a Sheet decision. Title-only screening must not be represented as full-description review and must not copy Source Hash into Description Hash.
SECOND PASS: lower-cost complete-description triage. Return ESCALATE, CLEAR_REJECT, or NEEDS_INFO. Normal submit automatically writes CLEAR_REJECT as Added to Opportunities? = No / Review Status = Reviewed / Decision = Reject. NEEDS_INFO writes Added to Opportunities? = Manual Review / Review Status = Manual Review / Decision = Needs Info. ESCALATE hands off to THIRD PASS. SECOND PASS is not final positive-fit review.
THIRD PASS: higher-capability independent final review of committed ESCALATE records. Return Accept/Reject/Needs Info, with Strong/Possible/Stretch for accepted jobs. Normal submit automatically writes and verifies the completed job or batch. Accept adds or updates the Opportunity and sets History to Yes; Reject sets No; Needs Info sets both Added to Opportunities? and Review Status to Manual Review.

For all three passes, finish attempts bounded local writeback and remote publication (default 25; --limit accepts 1–100), then performs the fresh completion check. Repeat finish or writeback if pending synchronization remains. Start and next do not drain old pending writes automatically. Retry saved local outcomes with ./job-search-reviewer publish --pass N --run-id RUN_ID --limit 100; omitting --run-id is a maintenance-only pass-wide retry and never starts reviews or takes claims.
The finish command must perform a fresh live queue read; do not use --local-only to claim completion. CONTINUE means process available work; WAITING_WORKERS means another worker in this pass owns unfinished jobs; WAITING_UPSTREAM means an earlier pass still has active workers. For either waiting state, wait briefly within this active session, renew your own lease as needed, and recheck. DRAINED confirms the whole pass queue is empty at that live check; DRAINED_WITH_EXCEPTIONS requires an explicit unresolved-items report. Finishing closes only this worker's run. Isolated conflicts or missing evidence stay deferred while other eligible work continues. Never claim a blocked or interrupted run completed.
